# Deribit MCP v2: design

Status: approved · 2026-10-13 · prototype: `packages/deribit-client` (branch `proto/deribit-client`)

## Why rebuild

Four things changed at once:

1. **Deribit publishes machine-readable specs.** [OpenAPI](https://docs.deribit.com/specifications/deribit_openapi.json) covers 186 methods and [AsyncAPI](https://docs.deribit.com/specifications/deribit_asyncapi.json) covers 43 channels. The current client wraps about 25 methods by hand, with hand-written parameter lists. The October audit found 9 places where those had drifted from the API: required timestamps, units, removed params, enums, strike formats, and partial ticker updates (#25, #29).
2. **MCP spec 2026-07-28 is stateless.** There is no `initialize` and no `Mcp-Session-Id`. Cross-call state needs explicit handles, and `tools/list` must not vary per connection. Cloudflare has deprecated and frozen `McpAgent` in favour of `createMcpHandler(factory)` with TS SDK v2 (`@modelcontextprotocol/server`). Today's design keeps credentials in a per-session Durable Object, which this model doesn't support.
3. **Tool count.** 31 thin per-endpoint tools is past the point (about 30) where MCP guidance suggests search plus execute. Exposing all 186 methods one by one would not scale either.
4. **Skills** now carry the domain knowledge (`skills/deribit`, #28), so tool descriptions can be short.

## Goals

- Every Deribit method is reachable, with params validated against the published spec. No hand-maintained parameter lists.
- Spec drift is detected automatically, not by an audit.
- At most about 12 tools in `tools/list`. Common questions take one call, and the rest goes through search and call.
- Compliant with MCP 2026-07-28, while still serving older clients.
- The same core runs as a hosted Worker and as a local stdio server.
- Two deployment modes: a hosted server for public market data, and a local server with the user's own key that also covers private methods. Nothing state-changing runs without a human confirming it.

## Non-goals

- Per-user credentials on the hosted server (no OAuth, no credential vault). Private access is local only.
- Claude connector directory listing for the local server. The directory doesn't accept tools that move funds; the hosted public-data server would still be eligible.

## Architecture

```
packages/
  client/        @deribit-mcp/client   generated from spec/, no MCP knowledge (prototype done)
  mcp/           @deribit-mcp/server   tools, formatting, auth modes; worker + stdio entries
skills/
  deribit/       public companion skill (#28); scripts/ import @deribit-mcp/client
```

**Local-only layer** (stdio). The hosted server can't keep state between requests; a local process can:
- **Live cache:** `src/live.js` keeps market subscriptions open after first use and answers from memory. Channels unused for `DERIBIT_LIVE_TTL` minutes (default 15) are dropped, so subscriptions last a working session, not forever. A dropped socket marks cached data stale until the resubscribe delivers fresh snapshots, and an LRU cap bounds the channel count.
- **`save_to`:** writes tables to CSV under `DERIBIT_OUTPUT_DIR`.
- **Proxy:** `HTTPS_PROXY` support for HTTP and WebSocket via `undici`.

Each package is self-contained for now; the server depends on the client via `file:../deribit-client`. The repo root still installs and deploys v1, and mixing in v2's dependencies (zod 4, MCP SDK v2, a newer `agents`) could break v1's CI. Move to npm workspaces with a root lockfile when v1 is retired.

### Layer 1: client (prototype exists)

The prototype provides:
- `call(method, params)` and `client.public.*` / `client.private.*`, sending the same JSON-RPC envelope over HTTP POST or WebSocket
- spec validation, with all problems reported in one error
- `snapshot()`, which merges incremental changes and replays the latest state to late subscribers
- `subscribe()`, `search()` and `check-spec`
- types for every method's params and result

It has no runtime dependencies. Offline and live tests pass.

Still to do:
- **Rate limits:** retry with backoff on HTTP 429 and Deribit error 10028 `too_many_requests`, honouring credit limits.
- **Batching:** batch helpers, e.g. `snapshotMany` with chunked subscribes, since Deribit caps the channels per subscribe.
- **Size:** trim descriptions in `methods.js` (342 KB) or lazy-load them, for the Workers bundle.

### Layer 2: MCP server

Runtime:
- **Entry points:** `createMcpHandler(factory)` (agents ≥ 0.20, SDK v2) for the Worker, with `legacy: "stateless"` for older clients, and `serveStdio(factory)` for local use.
- **Shared factory:** both entries share one `createServer({ client, mode })`.
- **WebSocket:** the WebSocket client is created once per Worker isolate, at module scope, and closes after 60 s idle (as in #26). Reuse is best-effort within an isolate. If one shared upstream connection becomes worth it, move it into a single "market hub" Durable Object.

#### Tools

Curated tools: one call each for the common questions. All of these are `readOnlyHint: true` and `openWorldHint: true`.

| Tool | Replaces | Notes |
|---|---|---|
| `options_chain` | get_options_chain(s) | `currency`, `underlying`, `expiries[]`, strike range or `moneyness` band, `fields` |
| `tickers` | get_ticker(s) | array of instruments, one WebSocket snapshot |
| `order_books` | get_order_book(s) | |
| `market_overview` | get_book_summary_by_currency, get_index_price(s) | top N by volume and OI, with a "showing N of M" note |
| `funding` | get_funding_rate, get_funding_rate_history | current plus history, with an annualised summary |
| `volatility` | get_volatility_index_data, get_historical_volatility | DVOL vs realised, aligned |
| `instruments` | get_instruments, get_expirations, get_combos | filters plus a `limit` |
| `account` | get_account_summary, get_positions, get_open_orders, get_user_trades, get_order_history | `view` enum; local mode only |
| `vol_surface` | — | Mark IV for every option of an underlying from one `markprice.options.{index}` message (about 1 s cold, 0.3 s warm for all 888 BTC options). The forward comes from put-call parity on the marks, and 25-delta strikes from Black-76 deltas on mark IV. Returns a term structure or smiles, without greeks; use `options_chain` when greeks are needed. |

Generic tools reach everything else:

| Tool | Behaviour |
|---|---|
| `deribit_search` | Wraps `search()`. Returns method or channel names with summaries. |
| `deribit_describe` | Full params, enums, required fields and description for one method. |
| `deribit_call` | Runs one **allowlisted** method with validated params and returns truncated JSON. |

Write tools exist only in local mode:

| Tool | Behaviour |
|---|---|
| `cancel_orders` | Curated cancel (`cancel_all_by_currency` / `by_instrument` / `by_label`), with `destructiveHint: true`. |
| `deribit_call_write` | Any other private method that isn't a `get_*` (81 in the current spec: orders, edits, transfers, API keys, MMP, block trades), with `destructiveHint: true`. |

Both need confirmation. On clients that declare elicitation they return an MRTR `input_required` confirmation that states the method and params. On others they require `confirm: true` in the arguments. Writes are a separate tool from `deribit_call` because annotations are per tool. Claude's directory rules also require separate read and write tools, and clients can then prompt only on writes.

Each method's class is generated from the metadata and checked in, so reviews see every change:

| Class | Methods | Hosted | Local |
|---|---|---|---|
| Public market data | `public/*` except the session methods (`auth`, `hello`, `set_heartbeat`, `subscribe`, `unsubscribe*`, `exchange_token`, `fork_token`), about 36 | `deribit_call` | `deribit_call` |
| Private read | `private/get_*`, 57 | — | `deribit_call` |
| Private write | every other private method, 81 | — | `deribit_call_write` |

Deprecated methods are excluded in both modes. Local mode also blocks the funds-moving and API-key methods by default (see Decisions). `DERIBIT_ALLOW` (method globs) re-enables specific ones, and `DERIBIT_DENY` blocks more.

A "code mode" `deribit_execute` tool (model-written JS in a sandbox calling the client) is deferred. `deribit_call` plus the skill's scripts cover most needs without running untrusted code. Revisit it once Cloudflare's sandbox loader is a settled option.

#### Output

- **Format:** tabular results (option chains, overviews, instrument lists, trade and funding history, account lists) come back as CSV: a one-line JSON header with metadata such as units, forwards and truncation, a blank line, then the table. Everything else is compact JSON. Every tabular tool takes `format: 'json'` to opt out. On live data CSV is 59–68% smaller than JSON. TOON is dropped.
- **Limits:** every list output has a default limit and says "showing N of M; narrow with …" when it truncates (Claude Code caps tool output at 25k tokens).
- **Errors:** they come back as `isError` results with actionable text. Validation problems list every bad param, which comes free from the client.

### Layer 3: skills

- **Public skill (`skills/deribit`):** keeps the knowledge and gains `scripts/` that import the client, such as `skew.mjs` (prototype in `packages/deribit-client/examples/`), `term_structure.mjs` and `funding_vs_basis.mjs`. Where code execution exists, a script does a multi-call analysis without routing every intermediate result through the model.
- **Private skills:** layer strategy, limits and account layout on top.

## Auth modes

| Mode | Credentials | Tools |
|---|---|---|
| **Hosted** (`mcp.x.zip/deribit/mcp`) | Server-wide key from Worker secrets (a read-only dummy account). Sent on **every** call, because Deribit's rate limits are per user when authenticated and per IP otherwise, and Workers share IPs. | Public market data only. Private tools are never registered, so the dummy account's balances and positions are never shown to anyone. |
| **Local stdio** | The user's own key from `DERIBIT_CLIENT_ID` / `DERIBIT_CLIENT_SECRET` / `DERIBIT_ENV`, as the spec recommends for stdio. | Public, private read, and private write (with confirmation). |

This removes `set_deribit_credentials` and `clear_credentials`, so secrets never pass through the model's context and there's no session state. The tool list differs between deployments, not between connections, which the spec allows.

Because the server-wide key is shared by every anonymous caller, the hosted server should rate-limit per client IP (Cloudflare rate-limiting rules) so that one heavy caller can't exhaust the key's quota for everyone.

## Drift and testing

- **Weekly CI job:** runs `npm run check-spec`. On drift it regenerates, runs the tests and opens a PR whose description lists the signature diff.
- **Client tests:** offline tests (stubbed fetch, fake socket) and type tests in CI, plus live public tests on a schedule rather than on every PR.
- **Server tests:** an in-memory MCP client test for every tool (schemas, truncation, error text, allowlist enforcement), plus a stdio smoke test that stdout carries only protocol messages.
- **Skill evals:** a handful of realistic prompts run with and without the skill, using the MCP server connected.

## Migration

1. **Merge the current fixes.** Done: #25 and #29 merged. #26–#28 were closed, and v2 covers what they did.
2. **Land the client package** on a workspace layout and add the `check-spec` CI job.
3. **Build `packages/mcp`** on SDK v2:
   - curated tools, plus `deribit_search` / `deribit_describe` / `deribit_call`
   - local mode adds the write tools behind confirmation
   - hosted mode uses the server-wide key and per-IP rate limiting
   - deploy as `deribit-mcp-v2` next to v1
4. **Point the skill** at v2 tool names and add the scripts.
5. **Retire v1** and `McpAgent`.

## Decisions

- **Hosted credentials:** no per-user auth on the hosted server. It is public data only, authenticated with the server-wide key for rate limits. Private access is local only.
- **Writes:** local mode exposes private methods, including writes, behind confirmation. The hosted server has none.
- **Output:** CSV for tables, JSON for everything else; no TOON.
- **Distribution:** GitHub, not the npm registry.
  - The client is published as a tarball attached to a GitHub Release, installable with `npm i https://github.com/azhang/deribit-mcp/releases/download/client-vX.Y.Z/deribit-mcp-client-X.Y.Z.tgz`. No npm account is needed, and installing needs no auth. GitHub Packages was ruled out because it requires a token even to install public packages.
  - Skills don't install anything: they carry a single-file ESM bundle of the client in `scripts/lib/`. The client has no runtime dependencies, so the bundle is self-contained.
- **Funds-moving methods:** local mode blocks them by default, even with confirmation. That covers `withdraw`, `submit_transfer_*`, `cancel_transfer_by_id`, `cancel_withdrawal`, address-book and beneficiary changes, and API-key management (`create_api_key`, `edit_api_key`, `remove_api_key`, `reset_api_key`, `change_scope_in_api_key`, `enable_api_key`, `disable_api_key`, `list_api_keys`). Setting `DERIBIT_ALLOW` re-enables specific ones.
