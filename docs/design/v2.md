# Deribit MCP v2: design

Status: draft · 2026-10-13 · prototype: `packages/deribit-client` (branch `proto/deribit-client`)

## Why rebuild

Four things changed at once:

1. **Deribit publishes machine-readable specs.** [OpenAPI](https://docs.deribit.com/specifications/deribit_openapi.json) covers 186 methods and [AsyncAPI](https://docs.deribit.com/specifications/deribit_asyncapi.json) covers 43 channels. The current client wraps about 25 methods by hand, with hand-written parameter lists. The October audit found 9 places where those had drifted from the API: required timestamps, units, removed params, enums, strike formats, and partial ticker updates (#25, #29).
2. **MCP spec 2026-07-28 is stateless.** There is no `initialize` and no `Mcp-Session-Id`. Cross-call state needs explicit handles, and `tools/list` must not vary per connection. Cloudflare has deprecated and frozen `McpAgent` in favour of `createMcpHandler(factory)` with TS SDK v2 (`@modelcontextprotocol/server`). Today's design keeps credentials in a per-session Durable Object, which this model doesn't support.
3. **Tool count.** 31 thin per-endpoint tools is past the point (about 30) where MCP guidance suggests search plus execute. Exposing all 186 methods one by one would not scale either.
4. **Skills** now carry the domain knowledge (`skills/deribit`, #28), so tool descriptions can be short.

## Goals

- Every Deribit method is reachable, with params validated against the published spec. No hand-maintained parameter lists.
- Spec drift is detected automatically, not by an audit.
- At most about 12 tools in `tools/list`. Common questions take one call, and the rest goes through search and call.
- Compliant with MCP 2026-07-28, while still serving older clients.
- The same core runs as a hosted Worker and as a local stdio server.
- Account tools stay available in every mode, and nothing irreversible runs without a human confirming it.

## Non-goals

- Order entry (`buy`, `sell`, `edit`, `withdraw`, transfers). Out of scope for now. It also rules out Claude's connector directory, which doesn't accept tools that move funds.
- A hosted multi-user credential vault before the auth model is settled (see open questions).

## Architecture

```
packages/
  client/        @deribit-mcp/client   generated from spec/, no MCP knowledge (prototype done)
  mcp/           @deribit-mcp/server   tools, formatting, auth modes; worker + stdio entries
skills/
  deribit/       public companion skill (#28); scripts/ import @deribit-mcp/client
```

npm workspaces, one lockfile committed at the root.

### Layer 1: client (prototype exists)

The prototype provides:
- `call(method, params)` and `client.public.*` / `client.private.*`, sending the same JSON-RPC envelope over HTTP POST or WebSocket
- spec validation, with all problems reported in one error
- `snapshot()`, which merges incremental changes and replays the latest state to late subscribers
- `subscribe()`, `search()` and `check-spec`
- types for every method's params and result

It has no runtime dependencies. Offline and live tests pass.

Still to do:
- **Rate limits:** retry with backoff on HTTP 429 and Deribit error 10028 `too_many_requests`, honouring credit limits.
- **Batching:** batch helpers, e.g. `snapshotMany` with chunked subscribes, since Deribit caps the channels per subscribe.
- **Size:** trim descriptions in `methods.js` (342 KB) or lazy-load them, for the Workers bundle.

### Layer 2: MCP server

Runtime:
- **Entry points:** `createMcpHandler(factory)` (agents ≥ 0.20, SDK v2) for the Worker, with `legacy: "stateless"` for older clients, and `serveStdio(factory)` for local use.
- **Shared factory:** both entries share one `createServer({ client, mode })`.
- **WebSocket:** the WebSocket client is created once per Worker isolate, at module scope, and closes after 60 s idle (as in #26). Reuse is best-effort within an isolate. If one shared upstream connection becomes worth it, move it into a single "market hub" Durable Object.

#### Tools

Curated tools: one call each for the common questions. All of these are `readOnlyHint: true` and `openWorldHint: true`.

| Tool | Replaces | Notes |
|---|---|---|
| `options_chain` | get_options_chain(s) | `currency`, `underlying`, `expiries[]`, strike range or `moneyness` band, `fields` |
| `tickers` | get_ticker(s) | array of instruments, one WebSocket snapshot |
| `order_books` | get_order_book(s) | |
| `market_overview` | get_book_summary_by_currency, get_index_price(s) | top N by volume and OI, with a "showing N of M" note |
| `funding` | get_funding_rate, get_funding_rate_history | current plus history, with an annualised summary |
| `volatility` | get_volatility_index_data, get_historical_volatility | DVOL vs realised, aligned |
| `instruments` | get_instruments, get_expirations, get_combos | filters plus a `limit` |
| `account` | get_account_summary, get_positions, get_open_orders, get_user_trades, get_order_history | `view` enum; needs credentials |

Generic tools reach everything else:

| Tool | Behaviour |
|---|---|
| `deribit_search` | Wraps `search()`. Returns method or channel names with summaries. |
| `deribit_describe` | Full params, enums, required fields and description for one method. |
| `deribit_call` | Runs one **allowlisted** method with validated params and returns truncated TOON. |

Write tools: `cancel_orders`, the only one, with `destructiveHint: true`. On clients that declare elicitation it returns an MRTR `input_required` confirmation; on others it requires `confirm: true` in the arguments.

The `deribit_call` allowlist is generated from the metadata and checked in so reviews see every change:
- **Allowed:** public market-data methods (excluding the session methods `auth`, `hello`, `set_heartbeat`, `subscribe`, `unsubscribe*`, `exchange_token`, `fork_token`) and private `get_*` methods. That's about 36 public and 57 private methods.
- **Excluded:** every other private method (81, all state-changing or sensitive, e.g. `list_api_keys`, `create_api_key`, `withdraw`, `submit_transfer_*`) and anything marked `deprecated`.

A "code mode" `deribit_execute` tool (model-written JS in a sandbox calling the client) is deferred. `deribit_call` plus the skill's scripts cover most needs without running untrusted code. Revisit it once Cloudflare's sandbox loader is a settled option.

#### Output

- **Format:** TOON text, as now.
- **Limits:** every list output has a default limit and says "showing N of M; narrow with …" when it truncates (Claude Code caps tool output at 25k tokens).
- **Errors:** they come back as `isError` results with actionable text. Validation problems list every bad param, which comes free from the client.
- **Structured output:** `outputSchema` / `structuredContent` only where a programmatic consumer needs it. Decide by eval, not by default.

### Layer 3: skills

- **Public skill (`skills/deribit`):** keeps the knowledge and gains `scripts/` that import the client, such as `skew.mjs` (prototype in `packages/deribit-client/examples/`), `term_structure.mjs` and `funding_vs_basis.mjs`. Where code execution exists, a script does a multi-call analysis without routing every intermediate result through the model.
- **Private skills:** layer strategy, limits and account layout on top.

## Auth modes

| Mode | Credentials | Private tools |
|---|---|---|
| Hosted, anonymous | Optional server-wide **rate-limit key** (read-only dummy account) | Not offered. The key is used for public calls only and is never reported as "authenticated". |
| Local stdio | `DERIBIT_CLIENT_ID` / `DERIBIT_CLIENT_SECRET` / `DERIBIT_ENV` from the environment, as the spec recommends | Yes |
| Hosted, per user | MCP OAuth through the Workers OAuth Provider. The consent page collects a Deribit API key, which is stored encrypted against the OAuth subject. Each request gets the key through the auth context; the MCP token is never passed to Deribit. | Yes |

This removes `set_deribit_credentials` and `clear_credentials`: secrets no longer pass through the model's context, and there's no session state. The tool list may vary by authorization, which the spec allows.

## Drift and testing

- **Weekly CI job:** runs `npm run check-spec`. On drift it regenerates, runs the tests and opens a PR whose description lists the signature diff.
- **Client tests:** offline tests (stubbed fetch, fake socket) and type tests in CI, plus live public tests on a schedule rather than on every PR.
- **Server tests:** an in-memory MCP client test for every tool (schemas, truncation, error text, allowlist enforcement), plus a stdio smoke test that stdout carries only protocol messages.
- **Skill evals:** a handful of realistic prompts run with and without the skill, using the MCP server connected.

## Migration

1. **Merge the current fixes** (#25–#29). They fix today's server, and v2 ports their behaviour.
2. **Land the client package** on a workspace layout and add the `check-spec` CI job.
3. **Build `packages/mcp`** on SDK v2 with curated tools, `deribit_search` / `deribit_describe` / `deribit_call`, and the stdio and hosted-anonymous modes. Deploy as `deribit-mcp-v2` next to v1.
4. **Point the skill** at v2 tool names and add the scripts.
5. **Add OAuth** per-user mode, then retire v1 and `McpAgent`.

## Open questions

1. **Per-user hosted credentials:** is OAuth worth it, or is "hosted is public-only, use stdio for your account" enough?
2. **Write scope:** keep `cancel_orders` at all, or make v2 strictly read-only? Read-only simplifies the auth model and directory eligibility.
3. **TOON vs JSON:** worth a small eval with the skill's prompts before committing.
4. **Publish the client to npm?** Only if something outside this repo will use it.
5. **Rate-limit key:** keep the server-wide key at all once per-user auth exists? It is shared quota for anonymous callers.
